## 2026-11-28 修订：所有画质共享动画时间线（待发布修复）

- 画质只改变材质、粒子、位移幅度和缓动曲线；按钮、面板、动作牌、转场、胡牌与翻鸡的开始阶段、等待时间和总时长必须一致。不得用画质决定操作入口何时出现。

## 一、iOS 动效设计原则与工程准绳

1. **弹簧物理（Spring Physics）**：精致档采用欠阻尼/临界阻尼弹簧（以响应时长 `response` 与阻尼比 `damping_ratio` 定义），让按钮按压、面板弹出、手牌抬落与筹码提示具备真实惯性与自然回弹；流畅档使用同源无过冲轻曲线（位移/缩放/透明度），保持节奏一致且零额外计算负担。
2. **全程可打断（Interruptible）**：任何按钮按压、面板开关、手牌选抬/拖拽、胡牌提示与转场均须持有独立句柄并在重入时立即 `kill()` 或平滑接管当前值，**绝不阻塞权威输入，绝不出现双 Tween 抢写或视觉回闪**。
3. **短时长利落（Snappy）**：
   - 微交互（按钮按下/抬起、开关、选牌）：`75–150 ms`；
   - 面板、弹窗、胶囊、页签：`160–280 ms`；
   - 牌的动作：严格遵守 `GamePace.ACTION_SECONDS = 0.30s`（300 ms）与发牌演示回执节奏，不拖慢出牌手感；
   - 场景转场：`220–360 ms`（告别原 `720 ms` 拖沓鱼眼缩放）。
4. **自然缓动（Natural Easing）**：全面消除生硬的 `TRANS_LINEAR`（如排序越顶折线）与突兀 `show()/hide()` 硬切；进场快起慢停（`EASE_OUT`），退场轻快收尾（`EASE_IN` / `EASE_OUT` 短时长）。
5. **音画严格同步（Audio-Visual Sync）**：音频播放必须等待首帧渲染就绪（特别是开局掷骰子音效），杜绝“画面尚在切换/编译着色器、声音已经播完”的割裂感。

## 二、双画质档位总体规范与性能预算

画质档位**完全复用既有配置系统**（`AppSettings.gd` 的 `quality: "smooth" | "detail"`、`quality_manual`、`power_save` 以及 `Main.gd` 的低帧自动降档与 `_apply_quality()` 总线），**不得另起第二套画质开关**。

| 维度 | 流畅档（`smooth` · 低端安卓保帧） | 精致档（`detail` · 中高端视觉旗舰） |
| --- | --- | --- |
| **允许使用的动效手段** | 仅位移（`position`）、缩放（`scale`）、透明度（`modulate:a`） | 弹簧回弹、柔和阴影层、微扫光/高光环、轻量阻尼微震、轻量 2D 池化粒子 |
| **明确禁用项** | 禁用粒子、禁用大面积模糊、禁用 3D 涟漪网格、禁用震屏、禁用常驻呼吸 `_process`、禁用装饰 SubViewport MSAA | 禁用全屏后处理模糊 Shader（移动端 GLES3 带宽杀手）、禁用 GPU 粒子着色器实时编译、禁用每帧 `new StyleBoxFlat()` |
| **目标帧率** | 低端安卓稳定 **60 FPS**（省电模式稳 30 FPS） | 中高端安卓稳定 **55–60 FPS** |
| **单帧动效 CPU 预算** | `≤ 0.4 ms`（零堆分配） | `≤ 1.2 ms`（对象/粒子预分配池化，零每帧堆分配） |
| **粒子预算** | `0` 颗 | 纯 `CanvasItem._draw()` 轻量池化粒子：单次爆发 `≤ 18` 颗、全局同时存活 `≤ 36` 颗 |
| **并发活跃 Tween 上限** | UI 层 `≤ 6`；3D 牌面仅必要位移 | UI 层 `≤ 16`；3D 牌面含微弧线与落位弹簧 |
| **显存增量预算** | `+0 MB`（并移除 `TitleTile`/`DicePairView` 流畅档 MSAA，反降显存） | `≤ +0.5 MB`（零新增大贴图，全部几何/纯色矢量与既有图集） |

## 三、集中动画参数配置表架构

### 1. 文件规划与职责
- **`remake/game/src/presentation/MotionConfig.gd`**（新建，纯配置表 + 当前画质单一真相源）：
  - 集中保存全项目所有动效的 `smooth` 与 `detail` 参数；
  - 维护 `static var current_quality := "detail"`，由 `Main._apply_quality(value)` 唯一更新；
  - 提供静态读取接口：`MotionConfig.get_spec(category, key)`、`MotionConfig.is_detail()`、`MotionConfig.set_quality(value)`。
- **`remake/game/src/presentation/MotionFX.gd`**（新建，可打断动效执行器 + 轻粒子池）：
  - `bind_button(button: BaseButton, style := "default")`：统一给任意 `Button` 挂载可打断按压/抬起/悬停微动效（自动设置中心 `pivot_offset` 并响应 `resized`）；
  - `animate_panel_in(node, backdrop = null, style := "modal")` / `animate_panel_out(node, backdrop = null, on_done = Callable(), style := "modal")`：统一面板/弹窗可打断进出场；
  - `animate_popup_show(node, from_offset := Vector2(0, 8))` / `animate_popup_hide(node)`：统一 Toast、听牌胶囊、抬牌提示进出场；
  - `spring_factor(t, response, damping_ratio)`：解析阻尼弹簧曲线函数（用于自定义 `_draw` / 3D 落位，零额外节点开销）；
  - `ParticleBurstPool`：轻量 2D 金箔/玉光粒子数组（最大容量 36，仅 `detail` 档启用，零节点创建、单次 `_draw` 批绘）。

## 五、转场重构与「开局骰子音画同步」专项方案

### 1. 彻底重构牌桌转场（[TableTransition.gd](file:///c:/Users/xiu/Desktop/Mahjong-Godot/remake/game/src/presentation/TableTransition.gd) + [Main.gd](file:///c:/Users/xiu/Desktop/Mahjong-Godot/remake/game/src/app/Main.gd)）

| 问题根因 | 优化方案 |
| --- | --- |
| **每帧重算相机取景导致卡顿**（`_apply()` 每帧调 `_table._frame_camera()` 遍历 50+ 牌 AABB） | `begin()` 阶段仅调用一次 `_table._frame_camera()` 并缓存 `_target_transform` 与 `_target_fov`，仅在 viewport `size_changed` 时才重算；转场期间 CPU 几乎为零。 |
| **首帧 GPU 预热吃掉前半段动画，造成冻结跳帧** | `begin()` 先将 `_board` 可见且 `_board_world` 设为 `UPDATE_WHEN_VISIBLE`，等待 **1 帧实际绘制完成**（`warmup_frames = 1`）后再开始推进 `_elapsed`，并钳制首帧 `delta <= 0.033s`，杜绝大步长跳帧！ |
| **无锚点进桌时 `1.65×` 高空 + `1.65×` 鱼眼 FOV 畸变，显得“不明所以”** | **彻底取消 FOV 畸变**（`fov_mult = 1.0`）：<br>• **流畅档（`0.24s`）**：温和微距俯视（`y * 1.06`）配合 `0.16s` 柔和淡入，干脆利落；<br>• **精致档（`0.36s`）**：优雅克制俯视入座推近（`y * 1.18`，iOS 过阻尼 `1 - (1-t)^3` 减速）+ `0.22s` 背景/牌桌交叉淡入 + 入座完成瞬间 HUD 轻量渐现；<br>• **有 3D 缩略桌锚点时**（点选房间座位入桌）：`t = 0` 精确对齐缩略桌四角（`< 35px` 满足 `test_lobby_flow`），随后以 `0.36s`（流畅 `0.24s`）顺滑过渡至最终视角，消除卡顿感。 |

### 2. 彻底修复「开局先听到骰子声、画面还没渲染好」（[SoundStage.gd](file:///c:/Users/xiu/Desktop/Mahjong-Godot/remake/game/src/audio/SoundStage.gd) + [Main.gd](file:///c:/Users/xiu/Desktop/Mahjong-Godot/remake/game/src/app/Main.gd)）
- **根因**：服务器进入 `phase == "dice"` 的同一帧 `SoundStage.accept_view()` 直接触发 `_effect("dice_roll")`，此时 Android GPU 仍在执行 `_board_world` 唤醒 + `show_full_wall()` 生成 108 张牌节点与首帧着色器预热，声音比画面早了 150–350 ms！
- **修复机制**：
  1. **视觉就绪门控**：`SoundStage` 新增 `var defer_dice_until_visual_ready := false`（`Main._ready()` 在非 headless 运行时置为 `true`；单元测试/headless 默认 `false` 直接播，100% 兼容 `test_audio.gd`）；
  2. 当 `accept_view()` 检测到 `phase == "dice"` 且门控开启时，不立刻播放，而是登记 `_pending_dice_sfx = true`；
  3. `Main.gd` 在 `_board.visible && _table.visible && _dice.visible` 且等待至少 `1` 帧实际渲染输出（`RenderingServer.frame_post_draw`）后，且当 `_transition` 已进入可见牌桌阶段时，立即调用 `_sound.notify_dice_visual_ready()` 精准放出 `dice_roll.wav`（附 `0.6s` 安全超时防丢声）；
  4. **牌节点轻量预热**：进入房间等待态或首次初始化 `TableView` 时预先创建/复用常用共享网格与材质引用，进一步把 `show_full_wall()` 首帧耗时压低至 `< 25ms`，确保“**一看见骰子落下，同步听到清脆掷骰声**”！
