# 联机网络模型

麻将是回合制游戏，本项目采用“状态同步 + 权威端校验”，不采用帧同步。局域网房主和云端 Godot 房间服务器都承担同一类权威职责；客户端只提交操作意图，不能直接修改牌局。

权威端负责洗牌、骰子、破墙、摸牌、判胡、碰杠胡窗口、结算、庄家和下一局状态。客户端提交出牌、碰、杠、胡、报听、准备、选座和换座请求。请求带座位号与 `prompt_id`，服务器会检查发送者是否拥有该座位、当前提示是否仍有效、操作是否符合规则，然后只广播新的完整状态快照。

快照通过 ENet 可靠通道发送，并带递增 `revision` 和 `round_number`。客户端丢包或乱序时丢弃旧 revision；状态更新合并在一帧内发送，避免同一动作触发多次重复刷新。音效事件带每局 session 和事件编号，重连不会重复播放历史语音。

## 断线与重连

玩家加入时生成 `resume_token`，成功入座后将凭证、房间地址/端口、房间号、名称和加入时的昵称保存到 `user://network.cfg`。重启会提示返回上次房间，主菜单和联机页也提供返回入口。凭证只用于恢复原座位，不能凭同一个房间号误入后来新建的房间。

断线后由 AI 立即接管；权威端保留原座位与凭证 5 分钟。等待下一局准备最多阻塞 30 秒，此后其他玩家可以与人机继续，离线者在 5 分钟内仍能回来接管同一座位，接收当时最新的手牌、累计分、局数和操作提示。新一局的准备状态不会沿用离线前上一局的状态。恢复成功前客户端禁止提交操作，座位分配和最新快照都到达后才解锁；结算局直接显示最终态。

游戏仍运行时的自动重试最多 5 次、间隔 5 秒；失败后仍保留本地凭证，联机页可再次点击返回。服务器明确拒绝过期凭证时清除记录；玩家主动离开房间会清除本地记录，并通知服务器释放座位。关闭窗口、系统终止进程不视为主动离开，重启可继续恢复。会话清除同时更新备份，避免旧凭证被备份恢复。

房主关闭局域网房间时，房间随主机结束；云端房间可继续运行。云端空房原有 60 秒回收不会中断有效的 5 分钟重连保留期。服务器进程本身重启不恢复旧牌局。网络连接只需要房间地址和端口，局域网模式通过发现服务自动得到地址，不要求玩家输入 IP。客户端与权威房间服务器须同步更新以使用新的恢复握手。

## 玩家名称

创建或加入房间前每位真人输入自己的昵称，长度限制为 16 个字符，输入时即保存到 `user://game_settings.cfg`，重启/覆盖安装更新后沿用。权威端保存昵称并在等待页和牌桌快照中同步；牌桌四个座位显示真实昵称，人机显示“人机 1”等。昵称不作为账号或身份验证。

联机模式、创建房间号、房间名及在线服务器地址也保存在 `user://network.cfg`，各设置写入时保留其余字段。无界面测试与专用服务器默认不读取或写入玩家个人设置；持久化测试使用独立临时路径。`tests/run_reconnect.py` 除短线重连外，还会强制终止客户端并启动新进程，验证游戏中/结算后的恢复、昵称、隐私、分数守恒、主动离开和同号新房间拒绝旧凭证。

## 云端部署边界

云端目录服务只负责列出房间和连接地址，牌局仍由房主或专用 Godot 房间服务器权威处理。生产环境应让客户端只连接权威房间端口，并在目录服务上设置房间过期时间、连接数限制和心跳监控。详细启动方式见 [server/README.md](../server/README.md)。
