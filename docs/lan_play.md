# 手机热点与局域网联机

## 手机开热点，电脑建房

1. 手机打开热点，电脑连接这个热点。
2. 两端在主菜单「检查更新」，更新到 1.0.1 或更新版本，完成后重启游戏。
3. 电脑打开「联机房间 → 局域网」，创建房间并停留在选座、准备页面。先不要准备开局。
4. 手机打开「联机房间 → 局域网」，等待房间自动显示，点击「加入」。无需输入电脑 IP。
5. 两端选择位置，全部真人准备后开局；人机默认准备。

电脑和手机连接同一个 Wi-Fi、手机建房电脑加入，也使用这个流程。

首次扫描一个 /24 网段通常需要数秒，存在多块私有网卡时可能更久。已发现房间会用定向查询保持列表更新。已经开局的房间不能加入。

## 仍找不到时

- 确认双方游戏菜单显示 1.0.1，且选择的是「局域网」。这次发现逻辑修复需要双方都更新。
- 确认电脑连接的是该手机的热点，不是另一个 Wi-Fi，电脑房主停留在等待页面。
- 手机系统应用联网设置允许本游戏访问网络；VPN、代理或设备隔离可能改变局域网通信路径。
- Windows 提示网络访问时允许游戏通信。热点常被 Windows 归为 Public 网络，需要游戏也获准在此网络通信。只允许麻将程序即可，不需要关闭系统防火墙。
- 路由器开启访客隔离或热点系统禁止设备间通信时，可换普通同一 Wi-Fi 测试。

## 实现与验证

联机协议采用可靠的状态同步和权威端校验，不采用帧同步。断线保留、resume token、昵称同步和快照 revision 的完整约定见 [network_model.md](network_model.md)。

`scripts/online/LanDiscovery.gd` 使用全网广播、绑定各 Wi-Fi/热点 IPv4 网卡的定向广播和单播查询。房主还向固定发现端口主动发送房间信息，使手机没有可见 AP 网卡时也能收到通知。扫描限于当前私有地址所在的 /24，不探测公网；大于 /24 的其他网络依靠广播发现。

查询端口为 7499～7508/UDP，主动通知接收端口为 7509～7518/UDP；游戏连接使用房主实际监听的 UDP 端口。房主通过包来源地址传递内部连接地址，UI 仍只显示房间。

验证命令：

```powershell
godot --headless --path . --script res://tests/smoke_lan_discovery.gd
python tests/run_network.py --godot "C:/Users/xiu/Desktop/Godot_v4.7.2-stable_win64.exe" --lan-interface
```

新增测试屏蔽所有广播、屏蔽客户端发包及热点网卡可见性，验证定向扫描和主动通知仍发现真实房间。`--lan-interface` 要求连接私有 IPv4 网卡，并通过真实网卡地址完成房间加入、选座、准备与整局同步。手机未通过 USB/ADB 连接时，不能代替真机确认。
