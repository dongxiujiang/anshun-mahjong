# 牌桌布局规范

版本：1.0；更新日期：2026-11-20。适用：安卓横屏牌桌及其发牌、摸打、碰杠、结算展示。

本文件记录用户已经明确提出的 UI 要求，以及为落实要求采用的实现参数。后续修改前先阅读本文件；技术参数和压力测试截图不能自动变成用户确认的设计，更不能变成游戏规则。

关联：[体验优化需求](项目体验优化需求文档.md)、[优化验收标准](项目体验优化验收标准.md)。玩法、计分、发牌与取牌逻辑仍以现有规则和代码为基线，布局修改不得改变它们。

## 1. 已明确的布局要求

| 编号 | 用户要求 | 布局约束 |
| --- | --- | --- |
| L01 | 自己和对家的弃牌之间有缝隙，需要挨紧 | 南北牌河按实际 3D 牌宽排布；不把二维像素间距直接当成模型间距。保留必要的牌体轮廓，不在牌间露出明显桌布缝隙 |
| L02 | 每家的幺鸡、八筒、碰杠优先放在自己手牌前面，居中 | 各家公开区围绕自己的手牌前方排布；不得默认塞向本家的左侧，挤占上家区域 |
| L03 | 先打的先放，后打的放在先打的右边，然后居中 | 以该玩家视角的左→右为顺序，独立鸡牌与碰杠组按首次公开事件混排；整组不拆散；空间不足时连续分行，不能按牌种或组长重排 |
| L04 | 每次普通出牌都挪动、闪烁，需要优化 | 本区公开牌未增减、未补杠且屏幕几何未变时，其他普通弃牌或其他玩家动作不得让本区重新居中。节点复用、静止帧和网络快照刷新不得改变落点 |
| L05 | 加杠先移动碰杠区，为原碰留出加杠位置，然后加杠 | 先让原三张和必要邻组平滑让位，再让第四张入位。保留原组首次公开顺序和牌实体；不让原三张重新飞一次，不改变杠的业务提交和补牌顺序 |
| L06 | 移除排序、上一种、下一种、恢复按钮与排法文字 | 所有相关按钮不可见且不接收点击；排法描述与其提示文字移除，不再为隐藏界面启动排法搜索。原有自动理牌行为保持 |
| L07 | 手牌移动到牌桌边缘，底部对齐；移除手牌下金线 | 自己的常规手牌和摸牌共用底边，不能根据张数跳动；结算平铺也使用一致底部基准。排法分组金线和近侧桌框金色嵌线不再显示 |
| L08 | 开局取满 13 张，手牌和动画位置不一致 | 4/8/12/13 张分批发牌的最终动画变换，与同一状态的实际手牌变换一致；不得落地重建后突然跳位 |
| L09 | 名字分数固定，不因拿完手牌而移动，且不能遮挡 | 四家身份区从发牌前到摸打、碰杠和结算保持固定。仅屏幕尺寸、安全区或设备密度改变时调整，不跟随实时手牌数量和投影边界 |
| L10 | 同一排主牌没有对齐 | 按各家主排靠近手牌的边缘对齐，不能按整组外框顶部对齐；多出的横牌/杠牌不能把主排带偏 |
| L11 | 对家供牌横牌在三张上方居中；上/下家供牌在三张左/右两侧同排 | 用户最终明确：侧家供牌的横牌放在三张的左侧或右侧，与三张同排，不放在三张上方端点；只有对家来源放在三张朝桌心的一侧居中。以杠牌者视角定义，所有观察方位只旋转同一摆法。保持实际供牌者，不改来源含义 |

L10、L11 的反馈来源：2026-11-20 的密集布局截图和真实回放 `step-63-view-0.png`。密集截图中重复牌仅用于占位压力测试，不能作为真实牌局示意。核对真实回放后，图中最右组实际为六条、来自画面右侧玩家；旧本家渲染特例把它放在三张上方右端，是本次应修的 UI 错误，不能当成用户认可摆法。用户比较两个视角后进一步明确“左右两侧”指同排两侧。对家来源通过明确供牌关系的专项验证。

## 2. 沿用的既有要求

- 南北普通弃牌每行 10 张、最多 3 行；东西每行 8 张、最多 4 行。行内贴近、行间紧凑；按镜头远近，屏幕下方牌遮挡上方牌底边。
- 普通弃牌与打出的幺鸡、八筒分区。鸡牌和碰杠共用公开区；保留横牌、庄家和报听状态的实际含义。
- 不恢复牌面的金色描边、冲锋鸡说明标记或姓名分数黑底。最新弃牌使用立体三角提示。
- 返回座位和准备下一局保留；底部按钮可以覆盖牌体底边，不能遮住有效牌面。删除整理工具栏不等于删除这两个按钮。
- 四家公开信息、翻鸡和桌上翻鸡牌应完整可读；不通过隐藏牌或改变牌源解决空间问题。

| 明杠共享几何 | 侧来源为端部横牌加三张同排；对家来源为三张主排加桌心侧居中横牌 | 本家不再独立覆盖相对坐标；牌桌、飞行落点和结算缩图均复用同一来源几何 |

## 4. 修改与验收办法

1. 每次修改先标明对应 L 编号。已有规范有明确答案时按规范处理；出现新的摆法选择时写清实施依据，不得记录为“用户已确认”。
2. 使用真实牌谱回放确认实际效果，按固定种子、相同操作和相同观察座位做前后对照；真实回放中同一牌不能凭空出现第五张。
3. 人工构造的极端布局另列为压力测试。截图和报告明确注明用途，不用这种图说明真实规则或请求用户确认正常对局效果。
4. 至少覆盖 4 个观察座位、4 个拥有者、明杠的 3 个来源、暗杠、补杠、独立鸡牌与混合顺序；明杠对家额外验证横牌相对三张主牌的实际 3D 中心线，左右来源额外验证端部位置。侧视角应沿牌组实际平面校验，不能直接用透视画面的轴对齐外框判断物理中心。
5. 开局分批发牌、普通出牌、邻家出牌、补杠让位与入位、结算平铺分别验证。落点测试必须比较实际 mesh transform，不能只检查二维槽位。
6. 通过条件同时包含：断言通过、无脚本/引擎错误、关键截图实际审看。仅日志出现 passed、仅最终分数不变或仅模型文件未改都不足以判定通过。
7. 旧测试如仍要求显示已删除的整理按钮，按 L06 迁移为隐藏/禁用检查，保留原有算法、牌实体、权限和印刷面断言；注册清单保留原有测试覆盖并增加新专项。迁移理由及原/新内容摘要登记在 `optimization_ui_test_migrations.json`。规则、AI、计分等断言不得修改。
