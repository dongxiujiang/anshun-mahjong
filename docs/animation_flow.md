# V2 牌桌动画流程

本文描述当前正式牌桌 `TableV2` 的实际动画路径。旧
`TableBoardView`、`PlayerTileAreas` 的遮罩动画仅保留兼容接口，正式画面不再使用。
牌墙编号、开口、取牌顺序和翻鸡条件以 [游戏规则总纲](游戏规则总纲.md) 为准。

## 0. 初始化、升墙和掷骰

开局由 `RoundState` 生成两层 54 列的牌墙，给每张牌固定的索引。任何座位看到的都是同一圈牌墙，桌面按观看者座位旋转，牌墙内的实际索引不变。

四面墙完整生成后，在骰子开始滚动时同步从桌内升起，模拟电动麻将桌。骰子停稳显示点数后才播放发牌。桌面依据真实槽位播放；拿走哪张、少哪张、下一张是什么由本局状态决定。

联机普通玩家同步各墩剩余张数和居中基准，取牌事件附带真实槽位索引；联机客户端不会得到还没翻开的整副牌面。迟加入和重连按收到的状态恢复已取走的槽位和当前墙的位置，不重新发牌。

## 1. 开局发牌

`RoundState` 按庄家、下家、对家、上家的顺序生成三个“每家四张”批次，再生成一个
“每家一张”批次。每次批次记录牌值与对应的 `deal_batch.deals[].indices`，联机按观看者隐藏其他玩家的牌面。动画按批次内的座位顺序播放。

```text
RoundState.deal_batch
  -> TableAnimationController 排队
  -> TableV2.animate_deal_group
  -> 从记录的真实墙槽起飞（四张一组时，飞行画面下层在左、上层在右）
  -> 到达每家手牌右侧临时落点
  -> 第二批、第三批让已有手牌向中间展开
  -> 四家都显示13张后停止发牌
```

开局没有预先铺好整副手牌的遮罩。手牌节点只按
`TableAnimationController.dealt_count(seat)` 显示已经落桌的牌，所以不会出现
“最终手牌被盖住后又闪一下”的情况。

每次只清掉离墙的牌，留下真实空格。每面墙第一次减到一半或以下时只居中一次：若正动画播放一组四张，整组取完再使用新的居中位置；之后的飞牌从实际显示的墙牌位置出发。

## 2. 理牌

四家各 13 张都落地后，`TableV2._begin_hand_sort()` 保留当前牌节点，仅把节点移动到
`Tiles.sort_hand()` 给出的槽位。每张牌用两段位置插值形成拱形轨迹，并逐张错峰。
理牌完成前输入保持锁定，完成后才播放庄家从牌头摸第 14 张。

## 3. 普通摸牌和杠后补牌

普通摸牌使用牌头。明杠、暗杠或加杠成立后，先播放碰杠落位和剩余手牌居中，再从整圈牌尾的真实槽位播放补牌。抢杠胡不播补牌。

```text
RoundState 发出 draw（head：普通摸牌；tail：杠后补牌）
  -> 记录目标座位并暂时隐藏摸牌位
  -> TableV2 从真实 wall_index 对应的牌墙块创建飞行牌
  -> 飞到该玩家的摸牌位并放大到手牌尺寸
  -> 飞行结束才显示正式摸牌节点
  -> 解锁玩家操作
```

自己的牌显示正面，其他三家显示牌背。飞行期间权威摸牌节点和普通手牌中的同张牌
不会提前显示，因此不会重复、闪烁或提前出现在右侧。

## 4. 有摸牌时的出牌

玩家刚摸牌后选择打出旧牌，依次执行：

1. 被选中的旧牌从手牌飞到弃牌区；鸡牌进入红色区。
2. 原有手牌节点保留，按最终顺序平移，把空位移动到插入点。
3. 右侧摸牌节点移动到新牌的空槽，并由 `draw_box` 转入 `hand_box`。

动画期间不重建整手牌，动画完成后只做一次权威快照校正。位置使用 V2 设计坐标，
不会先跳到左上角再刷新。

如果玩家直接打出刚摸的牌，则摸牌节点直接飞向弃牌区，手牌保持13张。

## 5. 无摸牌时的出牌

碰牌后可以不打新摸牌而直接出牌。这个回合没有摸牌位节点，因此执行：

1. 选中的手牌飞到弃牌区。
2. 其余手牌节点平移补位。
3. 动画结束后刷新权威状态。

它不会伪造摸牌位，也不会关闭空位后整手重建。

## 6. 碰杠与鸡牌

普通碰杠由 `TableV2.animate_meld()` 接管。静态重建和动画落点共用
`_meld_positions()`，所以动画结束后不会改用另一套坐标。

幺鸡、八筒的单张、碰和杠进入红色区。红色区的尺寸、间距、换行和固定锚点由
`TableV2Geometry` 与 `red_layout()` 统一计算；旋转后的实际边界使用
`RedLayer` 本地坐标系计算，避免在 Android 非等比缩放下与手牌或牌墙混算坐标。

## 7. 翻鸡和结算

结算翻开四家的真实手牌，把立着的手牌放平；碰杠、鸡牌和剩余牌墙仍留在桌上。有翻鸡牌时，动画从 `round_meta.flip_wall_index` 对应的真实墙槽开始：抬起、翻面，然后在原墩落下，或按规则总纲第 9.2 节移到下一墩顶部。源槽与落点可能不同，移动的只是这一张的画面。

需要移到下一墩时，汇总面板在飞行期间暂时让开，落位后再显示；面板布局须让桌上翻鸡牌完整可见。之后依次播放本局适用的得分展示，累计分数并进入结算完成状态。3D 桌面牌在翻鸡、鸡分和杠分阶段均保持原牌面，不给计分牌加金色描边；得分项目和分数动画正常显示。流局或胡牌时牌墙已空，省略桌上翻鸡动画和翻鸡预览，仍完成其余结算。

## 8. 对象池生命周期

频繁出现的牌统一由 `TileViewPool` 提供：

```text
acquire -> 重置牌面、尺寸、旋转、高亮和输入连接
        -> 加入目标图层
        -> 动画或快照重建结束
        -> release 回池
```

回收时必须同时恢复 `unit`、`custom_minimum_size` 和当前 `size`。否则从手牌或
摸牌位回收的大牌会在下一次作为红牌复用时保持错误尺寸，表现为冲锋鸡尺寸漂移。

`TableV2` 和旧 `TableAnimationLayer` 都在退出场景树时清空池内已经脱离节点的
TileView，防止连续切局积累 CanvasItem。
